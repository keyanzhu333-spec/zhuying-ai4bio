# LightDock Protein And Nucleic-Acid Docking

Use this skill for local rigid-body or ensemble docking in which both partners are represented as PDB structures. Supported task types are protein-protein, protein-DNA, and protein-RNA docking. The local environment is expected to provide a conda env named `lightdock`.

LightDock predicts candidate complex poses and ranks them with the selected scoring function. It is not an experimental binding-affinity measurement, and nucleic-acid poses should be treated as structural hypotheses for follow-up analysis or validation.

## Inputs

Preferred input layout:

```text
project/
├── case_a/
│   ├── receptor.pdb
│   └── ligand.pdb
└── case_b/
    ├── receptor.pdb
    └── ligand.pdb
```

Accept equivalent user-provided PDB paths by copying or linking them into a case directory as `receptor.pdb` and `ligand.pdb`.

For protein-nucleic-acid cases, use the protein as `receptor.pdb` and the DNA or RNA structure as `ligand.pdb`. Keep nucleic-acid chain IDs and standard residue names intact, for example `DA`, `DT`, `DG`, `DC` for DNA and `A`, `U`, `G`, `C` for RNA. Both partners must have valid three-dimensional coordinates; a FASTA file alone is not a docking input.

Before running, check that the nucleic-acid PDB has no duplicated atoms or unresolved alternate locations, and decide explicitly whether crystallographic waters, ions, cofactors, or modified bases belong in the model. Do not convert nucleic-acid residues to amino-acid records.

## Quick Workflow

1. Inspect the input PDBs and output directory. Do not overwrite unrelated prior runs unless the user asks.
2. For a known working local workflow, prefer `scripts/run_lightdock_batch.sh`.
3. Run inside the `lightdock` conda env.
4. Default to blind docking with ANM flexibility and `fastdfire` scoring for protein-protein cases. For protein-DNA/RNA cases, start with a rigid-body smoke test using `ANM_FLAG=""` unless the local LightDock installation has been verified to support ANM modes for the nucleic-acid partner.
5. Report the location of `rank_by_scoring.list`, `top_*.pdb`, and key command settings.

Default parameters:

```bash
SWARMS=400
GLOWWORMS=200
STEPS=100
SCORING=fastdfire
TOPN=10
ANM_FLAG=--anm
```

For quick smoke tests, use smaller values such as `SWARMS=50 GLOWWORMS=50 STEPS=20 TOPN=3`.

## Running

Use the bundled script when possible:

```bash
conda run -n lightdock scripts/run_lightdock_batch.sh /path/to/project case_a case_b
```

Or one case:

```bash
SWARMS=400 GLOWWORMS=200 STEPS=100 CORES=24 TOPN=10 \
conda run -n lightdock scripts/run_lightdock_batch.sh /path/to/project case_a
```

The script expects each case directory to contain `receptor.pdb` and `ligand.pdb`.

## Outputs

Each case directory will contain:

- `setup.json`
- `swarm_*` simulation directories
- `rank_by_scoring.list`
- `rank_by_rmsd.list` when generated by LightDock
- `solutions.list`
- `top_1.pdb` through `top_N.pdb`

When summarizing results, read `rank_by_scoring.list` and list the top scores and corresponding `top_*.pdb` files.

## Notes

- LightDock is CPU-based and can take a long time for full-length proteins. Use `CORES` to control parallelism.
- ANM flexibility is useful for protein-protein docking but increases cost. Set `ANM_FLAG=""` to disable it; this is the recommended starting point for protein-DNA/RNA runs.
- Clean PDBs before docking when needed: remove waters, alternate locations, unsupported hetero atoms, or extra chains not meant for docking. Preserve DNA/RNA backbone and base atoms that are part of the modeled interface.
- For protein-DNA/RNA results, inspect base contacts, backbone contacts, electrostatic complementarity, and chain orientation separately; a favorable LightDock score alone is not sufficient evidence of a biological binding mode.
- For detailed commands and troubleshooting, read `references/lightdock_workflow.md`.
